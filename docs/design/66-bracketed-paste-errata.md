## 1. Purpose, scope, and precedence

The user report is *"I can't paste into ymh from clipboard"*. This errata pins
the fix for the live supervisor TUI path (`src/ui/supervisor.cpp`,
`run_supervisor`; spec 17 §1). It is **additive**: one terminal-control
lifecycle, one event-stream reassembly state machine, and one bulk composer
insert. It introduces no wire, model, or persistence change.

**Precedence.** This errata wins over `10 §8.3` for the `TerminalCapabilities`
field list (the decorative `bracketedPaste` field is removed) and over `45 §6`
for input dispatch (a bracketed-paste run is captured before every modal/key
branch). It does not touch `58-E8`: the child composer stays read-only.

**Gate (per `AGENTS.md`).** Independent Oracle review marked this `verified`
(round 3 PASS, 0 HIGH / 0 MEDIUM; rounds 1-2 findings all closed).

## 3. Verified root cause (empirical, not derived)

The vendored FTXUI has **no** bracketed-paste support: no `EnableBracketedPaste`,
no `\x1b[200~` handling (`build/_deps/ftxui-src` — regenerated by FetchContent,
so it is not a fix target). Its POSIX reader reads raw stdin bytes and feeds
`TerminalInputParser::Add(char)` one byte at a time
(`build/_deps/ftxui-src/src/ftxui/component/screen_interactive.cpp:174-191`).

A hermetic probe drove the vendored parser with `\x1b[200~ab\ncd\x1b[201~`:

```
event[0] Special  "\x1b[200~"     (ignored by every ymh handler)
event[1] Character "a"
event[2] Character "b"
event[3] Return    "\n"           <-- the drop point
event[4] Character "c"
event[5] Character "d"
event[6] Special  "\x1b[201~"     (ignored)
```

**Root cause.** An embedded paste newline is delivered as `Event::Return`, which
`handle_input` treats as submit (`src/ui/supervisor.cpp:3402`: the Return branch
of `handle_input`, `:3328`). A multi-line paste therefore submits at the first
newline and the remaining text lands in the next draft, while the two markers
are silently dropped. The `TerminalCapabilities::bracketedPaste` flag
(`include/ymh/ui/terminal_layer.hpp:17` pre-fix) was set from `$TERM` but never
read: nothing emitted DECSET 2004, so a terminal that does wrap pastes produced
markers the TUI ignored, and one that does not produced raw newlines that
submitted.

`66-U7` reproduces this mapping in the suite: it feeds the raw byte sequence to
the real `ftxui::TerminalInputParser` and then drives the produced events through
the real handler (`tests/unit/errata66_ui_test.cpp`).

## 4. Design

### 4.1 Seam (decision 66-D1)

The fix lives in **ymh's own event stream** at the `handle_event_inner` boundary.
Rejected alternatives:

* **FTXUI patch under `build/_deps`** — the tree is regenerated by FetchContent;
  a patch is erased on the next configure. Rejected.
* **Pre-processing the stdin stream in ymh** — FTXUI owns the stdin reader
  (`EventListener`, `screen_interactive.cpp:174-191`); replacing it means
  reimplementing `ScreenInteractive`, far more invasive than reassembling its
  coherent event output. Rejected.
* **ymh event-stream reassembly** — the parser already delivers the open marker,
  the body, and the close marker as a contiguous run of `Event::Special` /
  `Event::Character` (`§3` probe), so a stateful interceptor reconstructs the
  paste exactly. **Chosen.**

### 4.2 Enable / restore (decision 66-D2)

`write_bracketed_paste(bool, int out_fd)` writes `\x1b[?2004h` / `\x1b[?2004l`
(`terminal_layer.cpp:20-44`). `TerminalLayer::enterBracketedPaste` emits DECSET
2004 on `STDOUT_FILENO` **only when stdout is a tty**
(`terminal_layer.cpp:52-61`); `leaveBracketedPaste` emits DECRST 2004 and is
idempotent (`terminal_layer.cpp:63-69`). The destructor restores it on every
non-signal exit (`terminal_layer.cpp:46-49`). Emission is **unconditional on a
tty**: DECSET 2004 is not introspectable and a `$TERM` false negative would
reintroduce the bug, while terminals that do not implement it ignore the mode.
The decorative `TerminalCapabilities::bracketedPaste` field is **removed**
(66-A1) so no capability lies about support that is never probed. `00 §20.19`
and `10 §8.3` still print the field literally; this errata supersedes it by
reference (recorded in the DESIGN_STATUS row).

### 4.3 Reassembly (decision 66-D3)

`SupervisorApp::handle_paste_event` runs at the top of `handle_event_inner`
(`supervisor.cpp:3703-3749`, called at `:3790`):

1. `Event::Special("\x1b[200~")` → arm: record the clock. If a run was already
   armed (a malformed nested marker), flush it first rather than dropping it
   (`:3708-3714`).
2. While armed, every event is **content**: `event.input()` is appended
   (`:3744`), including `Event::Return` (`"\n"`), `Event::Tab` (`"\t")` and any
   escape run the parser produced. `Event::Custom` still drains daemon replies;
   mouse/cursor-position/cursor-shape events are terminal-protocol events, not
   paste bytes, and are ignored (`:3737-3742`).
3. `Event::Special("\x1b[201~")` → disarm and flush.

**Parser normalization (66-I3, R1).** The bytes ymh receives are the bytes in the
emitted event's `input()`. They are not always the bytes the user pasted: FTXUI
applies `g_uniformize` to every `SPECIAL`
(`build/_deps/ftxui-src/src/ftxui/component/terminal_input_parser.cpp:138-145`;
table `:58-91`), so a legacy F-key encoding such as `\x1b[11~` arrives as
`\x1bOP`; and `ParseUTF8` drops malformed UTF-8 outright (`:227-262`). Neither
is recoverable inside ymh without the rejected seam (66-D1); both are inside a
paste only if the pasted text itself contains terminal escape sequences. The
limitation is scoped in 66-I3/F1 and pinned by `66-U10`.

State: `paste_active_` / `paste_buffer_` / `paste_last_event_at_`
(`supervisor.cpp:3957-3959`), **UI-thread only**. Lifetime:

| State | Created | Destroyed | Survives restart? | Crash |
|---|---|---|---|---|
| `paste_active_`, `paste_last_event_at_` | `SupervisorApp` construction; re-armed at each open marker | close marker (`:3733`) / idle flush (`:3727`); app teardown | no (never persisted) | lost with the process; no draft mutation was committed |
| `paste_buffer_` | armed open marker; appended per content event (`:3744`) | close/idle flush (moved into the draft), byte-cap flush (`:3745`), app teardown | no | lost with the process |
| `g_bracketed_paste_out_fd` (66-D5) | `BracketedPasteSignalGuard` ctor while paste is active (`:3889`) | guard dtor, and by the handler after it writes (`:103`) | no | signal path writes DECRST then dies |
| `saved_[]` dispositions (66-D5) | guard ctor | guard dtor | no | process death leaves the OS default table |

### 4.4 Bulk insert (decision 66-D4)

`flush_paste` (`supervisor.cpp:3755-3787`) performs **one** `draft.insert` at the
caret and advances the cursor by the inserted byte length — no per-character
`refresh_hints`, no Return handling, **no submission** — then refreshes hints and
marks `UiDirtyFlag::Input`. The paste is inserted into the active session's
composer, falling back to `pendingComposer` when no workspace exists
(`:3761-3766`). Embedded newlines become literal draft newlines that spec 59
wraps. In the read-only child view (58-E8) the paste is discarded rather than
mutating the frozen composer (`:3758-3760`) — the one deliberate "not inserted"
case, bounded to that view (66-I3).

**Modal interaction (decision 66-D8, M1).** A modal that owns the keyboard
captures the composer at open and restores it at close
(`capture_modal_composer`/`release_modal_composer`, `:2184-2216`). A paste made
while the modal is up mirrors its insert into the live snapshot as well
(`:3775-3780`), so `release_modal_composer` can no longer overwrite it. A
regression test (`66-U8`) pins this. The snapshot's `command_hints` are kept in
step too (`:3790-3792`), so a close does not restore pre-paste completion hints.

### 4.5 Degradation (decisions 66-D5, 66-D6)

* **Signal / abnormal exit (66-D5, M4).** FTXUI's `Install()` owns SIGINT,
  SIGTERM, SIGSEGV, SIGILL, SIGABRT and SIGFPE and turns them into a graceful
  loop exit (`build/_deps/ftxui-src/src/ftxui/component/screen_interactive.cpp:625-627`);
  `run_loop` then reaches `terminal.leaveBracketedPaste()`, which is called
  immediately after `quit_.store(true)` and before `timer.join()`
  (`supervisor.cpp:3944-3948`), so no signal window opens after the loop.
  `BracketedPasteSignalGuard`
  (`supervisor.cpp:117-150`) therefore installs an async-signal-safe handler
  (`:96-115`) for the two catchable signals FTXUI does not own: **SIGHUP and
  SIGQUIT** (`kSignals`, `:148`). The handler saves/restores `errno`, writes
  DECRST 2004, then re-delivers via `kill(getpid(), sig)` after setting
  `SIG_DFL`. FTXUI's SIGWINCH/SIGTSTP handlers are never touched.
* **Truncated run (66-D6).** A missing close marker is bounded two ways: a byte
  cap (`kMaxPasteBytes`, `:82`) that flushes the buffer but keeps the run armed
  (the rest of a large paste must not dispatch as keys), and an idle gap
  (`kPasteIdleFlush`, `:83`, `:3726`) that flushes **and disarms**, letting the
  next key dispatch normally. If the terminal never sends markers, pasted bytes
  reach the draft as ordinary input (unchanged behaviour).

## 5. Invariants

* **66-I1** On a tty, entering the TUI emits `\x1b[?2004h` exactly once; leaving
  emits `\x1b[?2004l` exactly once, on normal, FTXUI-handled signal, and error
  exits. SIGHUP/SIGQUIT are handled by the guard; SIGINT/SIGTERM/SIGSEGV/SIGILL/
  SIGABRT/SIGFPE by FTXUI's graceful exit calling `leaveBracketedPaste`. Two
  residual windows are excluded and recorded: the interval between
  `enterBracketedPaste` and FTXUI's `Install()` (its handlers are not installed
  yet), and `SIGKILL`/`SIGSTOP`, which are uncatchable. The signal path itself is
  not hermetically testable; 66-U5/U6 pin the bytes and the normal restore.
* **66-I2** A `\x1b[200~` … `\x1b[201~` run produces exactly one draft mutation
  and zero `session.submit`/`agent.prompt` calls, regardless of the number of
  embedded newlines.
* **66-I3** Every byte contained in the `input()` of the `Event::Character` /
  `Event::Special` events between the markers reaches the draft, including `\n`,
  `\t`, and valid UTF-8. This is **modulo FTXUI's parser**: `g_uniformize`
  rewrites legacy F-key/mouse encodings (e.g. `\x1b[11~` → `\x1bOP`) and
  malformed UTF-8 is dropped before ymh sees it (see §4.3). Terminal-protocol
  events (`Event::Custom`, mouse, cursor position/shape) are not paste bytes and
  are not appended; a paste in the read-only child view (58-E8) is deliberately
  not inserted.
* **66-I4** The paste is inserted at the caret; bytes after the caret shift.
* **66-I5** `paste_active_` is cleared by the close marker and by the idle
  flush; a byte-cap flush empties `paste_buffer_` but keeps the run armed until
  one of those two. A malformed run never suppresses later input.
* **66-I6** `Event::Custom` delivered mid-paste still drains daemon replies.
* **66-I7** While a child is viewed (58-E8) a paste does not mutate the draft.
* **66-I8** A paste made while a modal owns the keyboard survives the modal's
  composer restore.

## 6. Failure modes

* **66-F1 (F3 stream corruption)** — a `Character`/`Special` sequence inside the
  pasted text is inserted as the event's `input()` bytes and is never
  re-interpreted as a key. It is not byte-verbatim for the encodings FTXUI
  normalizes or drops (66-I3/§4.3).
* **66-F2 (F7 wrong action)** — an embedded newline is a literal draft newline,
  never Enter/submit.
* **66-F3 (F1 drop)** — a missing close marker is bounded by `kMaxPasteBytes`
  and `kPasteIdleFlush`; buffered text is inserted, never dropped. A nested open
  marker flushes the accumulated run before re-arming.
* **66-F4 (F1 drop)** — an idle gap mid-run flushes and returns the triggering
  event to normal dispatch.
* **66-F5 (F10 terminal corruption)** — DECRST 2004 is restored on the signal
  path (SIGHUP/SIGQUIT) and by FTXUI's graceful exit for the signals it owns; a
  write failure to a closed tty is ignored (no sequence is left half-written
  because `write_bracketed_paste` loops to completion).
* **66-F6 (F8 permission)** — none: paste mutates only the local draft; it
  cannot submit or execute.
* **66-F7 (F1 drop)** — a paste made while a modal owns the keyboard is mirrored
  into the modal composer snapshot, so closing the modal does not discard it.

## 8. Decisions

* **66-D1** Seam = ymh event-stream reassembly (not an FTXUI patch, not stdin
  pre-processing). See §4.1.
* **66-D2** Emit DECSET/DECRST 2004 on a tty, unconditionally; delete the
  decorative capability field. See §4.2.
* **66-D3** Reassembly state machine at `handle_event_inner`. See §4.3.
* **66-D4** One bulk insert, literal newlines, never submit; 58-E8 respected.
  See §4.4.
* **66-D5** Restore on signals via an async-signal-safe handler for the signals
  FTXUI does not own (SIGHUP/SIGQUIT); SIGINT/SIGTERM restore through FTXUI's
  graceful exit. See §4.5.
* **66-D6** Bounded degradation (byte cap keeps armed + idle flush disarms); no
  marker-less terminal is worse off than before. See §4.5.
* **66-D7 (rejected)** A modal "paste preview" dialog: no correctness gain, new
  `UiMode` state for nothing (cf. 19 §11 rule 5). Rejected.
* **66-D8 (M1)** A modal-owned composer snapshot is kept in sync with a paste so
  the close does not drop it. See §4.4.

## 10. Non-goals

* Mouse, OSC 52, or clipboard-manager integration (unchanged: `mouse = false`).
* `modifyOtherKeys`/kitty keyboard protocol.
* Pasting into modals other than the composer: a paste while a dialog is open is
  captured into the composer (and its snapshot, 66-D8), never dispatched to the
  modal.
